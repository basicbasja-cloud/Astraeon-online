## สิ่งที่เปลี่ยนจริง

เก็บคีย์เดิม8ภาพและเวลาเดิมทั้งหมด รวมเวลา1900ms คีย์เดิมอยู่ที่ output0,2,4,6,8,10,12,15 และให้ผล browser buffer เหมือนชุดก่อนทุกพิกเซล (`parent-key-render-review.json`) ท่าคั่น8ภาพใช้ raw **attempt2 ทั้งสองแถว** จาก v48 จึงเปลี่ยนท่าคั่นช่วงลุก4ภาพที่ v48 เคยเลือกจาก attempt4 ด้วย ไม่ใช่การย้ายพิกัดของภาพ16เดิมทุกภาพอย่างเดียว

กำหนด origin ร่วมของแถวภาพท่าคั่นสองค่า: บน(0,-3), ล่าง(0,+28) ปรับจาก raw cell0และ5เท่านั้น แล้วตรวจท่าคั่นที่เหลือ6ภาพและคีย์เดิม8ภาพเป็น held-out รวม14เฟรมต่อพื้นผิว ภาพในชุดเคยผ่านการดูในv48แล้ว จึงไม่ใช่blind testหรือชุดทดสอบที่ไม่เคยเห็น เป็น metadata ของแผ่นวาดสองแถว ไม่ใช่ผลตรวจข้อต่อหรือการ pin เท้าภายหลังรายเฟรม สเกล1ตลอด

v48ยังเป็นหลักฐานที่ไม่ผ่านสัญญา origin เดิม เราไม่แก้ไฟล์เก่าหรือเปลี่ยนเกณฑ์เพื่อให้ผลเก่าผ่าน สัญญาใหม่และแผนเลือกภาพอยู่ใน `layout-contract.json` และ `build-player.py` โดยเปิดเผยครบ

## ผลตรวจและขอบเขต

| พื้นผิวที่มองเห็น | ช่วงแกว่งขอบซ้าย/ขวา/Y (px) | เกณฑ์ X/Y | ผล |
|---|---:|---:|---|
| รองเท้าด้านซ้ายจอ | 3 / 2 / 2 | 6 / 6 | ผ่าน |
| รองเท้าด้านขวาจอ | 2 / 4 / 2 | 6 / 6 | ผ่าน |

ชื่อด้านจอไม่ใช่การเดาว่าเป็นข้างซ้าย/ขวาทางกายวิภาค เครื่องมือตรวจ alpha ของ connected component ในหน้าต่างที่ผู้ตรวจระบุ และพิจารณาแถบปลาย8px ไม่ใช่ตัวตรวจ skeleton อัตโนมัติ ภาพว่าง มีหลาย component ที่เป็นไปได้ หรือหน้าต่างตัดรองเท้าจะให้ UNKNOWN และไม่ผ่าน

`contact-qa.json` มี11กลุ่มตรวจ รวมชุดเด้งเดิมจริง ภาพเปลี่ยน SHA ภาพหาย หน้าต่างกำกวม การเด้ง8pxที่จงใจใส่ ตารางสัมผัสพื้น และตัวละคร KayKit ที่ขนาด/รูปร่าง/สีต่างกัน `clock-qa.json` มี10กลุ่มตรวจ: ข้ามเวลามาก/น้อย loop seek และ cancel รวม cancel จาก event callback ต้องหยุดตรงเวลาevent ไม่ส่งattach/storeต่อ ตัวอย่าง event เป็นสัญญาสาธิต ไม่ใช่หลักฐานการกำวัตถุที่ผ้าคลุมบัง และไม่ทำ inventory จริง

`browser-qa.json` ตรวจทุกเฟรม เล่นจริงทั้ง1×/0.25× loop pause และขอบเขตปุ่ม ใช้ไฟล์ clock เดียวกับเครื่องมือใช้ซ้ำ `pixel-audit.json` ตรวจ alpha เท่ากันทุกพิกเซล และ RGB แบบ premultiplied ต่างไม่เกิน1จากการปัดเศษของ browser ภาพดิบไม่เปลี่ยน ข้อความว่า RGBA ดิบทุกช่องเหมือนกันหลัง browser จะไม่ถูกต้อง โดยเฉพาะ RGB ที่ alphaต่ำ ภาพต้นฉบับไม่มี pixel alpha255 จึงต้องอ่านจำนวน pixelและหลักฐาน premultiplied ด้วย ไม่ใช้เงื่อนไข opaque อย่างเดียว

ผลผ่านนี้คือ **พื้นเท้าที่มองเห็นของท่าก้ม N16** การก้ม/ลุกยังเป็นการแสดงท่าเดิม (หัวเคลื่อนแนวดิ่ง128pxตามขอบalpha128 จึงไม่ได้ตรึงทั้งตัว) จังหวะลุกยังเน้นช่วงสั้นตาม8คีย์แม่ ไม่ใช่คำรับรองว่าความเร่ง/ทุก contour สมบูรณ์แบบ มือขวากับอัญมณีอ่านได้ในช่วงยกกลับ มือซ้ายว่าง แต่ขณะเอื้อมถูกผ้าคลุมบัง ห้ามใช้ผลพื้นเท้าแทนหลักฐานนิ้ว/ข้อศอกที่ซ่อนอยู่

ยังไม่ใช่การอนุมัติทั้ง8มุม สัดส่วนเทียบconceptทุกส่วน การแยกcomplete_head/body_outfit การเปลี่ยนหัว หรือการรวมเข้าเกม `production_pass=false` และไม่มีการอ้างว่าไม่มีข้อผิดพลาดที่ตรวจไม่เห็น

## ตรวจซ้ำ

รันจากราก repository; Pythonต้องมี Pillow/NumPy/SciPy และ Playwright สำหรับ browser

```sh
python3 tools/sprite-contact-review.py research/sprite-animation/pickup-contact-v49/contact-case.json --require-contact
python3 research/sprite-animation/pickup-contact-v49/test-contact.py
node research/sprite-animation/pickup-contact-v49/test-clock.cjs
python3 research/sprite-animation/pickup-contact-v49/test-browser.py
python3 research/sprite-animation/pickup-contact-v49/verify.py
```

คำสั่ง before-contact-case.json กับ `--require-contact` ต้อง exit1 ส่วน verify.py อ่านอย่างเดียว หลังเผยแพร่ห้ามรัน author/export ทับหลักฐาน case นี้ ให้สร้าง caseใหม่ พร้อมเก็บ provenance อ้างกลับมา

# วิธีใช้ซ้ำและตรวจงาน

เริ่มจากภาพต้นฉบับที่อนุมัติ ขนาดแคนวาส จุดพื้น และแกนอ้างอิงที่ชัดเจน แบ่งชิ้นภาพและระบุเจ้าของซ้าย/ขวาในท่าพักครั้งเดียว อย่าปรับขนาดตัวละครตามกรอบภาพของแต่ละท่า เพราะท่าก้มจะเด้งกลับสูงเท่าท่ายืน อย่าย้ายรองเท้าหรือวางรองเท้าทับผลลัพธ์ทีละเฟรม

ก่อนแปลงแอนิเมชัน ให้ตรวจความหมายของกระดูกจริง ไม่ใช้ชื่อเป็นหลักฐานว่าชี้แกนเดียวกัน กระดูกหัวต้นฉบับชี้ไปด้านหลัง แต่เรฟอีกริกชี้ขึ้น การอ่านเส้นหัวกระดูกเป็นแนวตั้งทำให้มุมหลังพลิก180องศา วิธีที่ใช้จริงคือหมุนเวกเตอร์ world-up ด้วยการหมุนหัวที่อ่านจากไฟล์ริก แล้วฉายผ่านกล้อง

สัดส่วนแขนต่างกันทำให้การคัดลอกมุมกระดูกอย่างเดียวเปลี่ยนตำแหน่งกำปั้น ท่าหมัดชุดนี้รักษาตำแหน่งข้อมือเทียบกับหัวไหล่ของเรฟ ใช้ตัวคูณความยาวแขนคงที่หนึ่งค่าต่อข้าง แล้วแก้ IK ด้วยความยาวกระดูกเดิมและระนาบข้อศอกของเรฟ ข้อมือกำปั้นคงแนวเทียบกับท่อนแขน วิธีนี้เป็นการดัดแปลงอยู่กับที่ ไม่ใช่การคัดลอกการก้าวพุ่งทั้งหมด

ภาพแขนที่พอสำหรับท่าเดินอาจมีส่วนที่ซ่อนอยู่ไม่ครบ อย่านำขอบผ้าคลุมหรือชิ้นแขนที่ถูกบังไปยืดเป็นท่อนแขนเต็ม ต้องเตรียมชิ้นเต็มหรือ underlap ที่มีที่มา จุดข้อมือต้องอยู่ตรงขอบเกราะ/ถุงมือของชิ้นภาพจริง: มุม N เคยใช้ข้อมือ323กับชิ้นใหม่ซึ่งขอบอยู่313 ทำให้ตัดกลางกำปั้น แม้ตัวเลขริกจะผ่าน

ชิ้นเกราะที่คร่อมข้อต่อต้องมีเจ้าของชัดเจน มิฉะนั้นจะเกิดเกราะซ้ำเมื่อพับแขน ชุดนี้อนุญาตเฉพาะ underlap เสื้อสีเข้มที่ระบุไว้ใน UV ท่าพัก พร้อมขอบข้อศอกโค้ง ขอบเกราะเคลื่อนไหวตามท่อนแขนเดียวกัน ส่วนข้อมือ/กำปั้นเป็นชิ้นแข็ง โปรไฟล์สี/UV นี้ต้องตรวจใหม่เมื่อวัสดุหรือตัวละครเปลี่ยน เครื่องมือไม่ได้อนุมานกายวิภาคจากสี

การเปลี่ยนท่าพักและช่วงถ่วงน้ำหนักทำครั้งเดียวกับทั้งคลิปได้ แต่การค้นหาค่าต้องใช้ริก/เรขาคณิตและผ่านภาพจริงต่ออีกชั้น ชุดนี้ตรวจเมชขา>.15 ส่วนท่อนแขนที่ฉายเกือบเข้าหากล้องตรวจว่าทุกสามเหลี่ยมตรงกับอัตราส่วน affine ของกระดูกนั้น ไม่ใช้เกณฑ์เดียวกันไปเรียกการย่อสั้นตามกล้องว่าเมชพับ การทดสอบเชิงตัวเลขไม่ได้อนุมัติภาพโดยลำพัง

ตรวจเป็นชั้นตามลำดับนี้:

1. เปิดไฟล์ริกที่บันทึกจริง อ่านการเคลื่อนไหวหลายเวลา ตรวจความยาวกระดูก พื้น และตำแหน่งข้อมือที่ตั้งใจไว้ ใน Blender ให้ใช้ fake user กับ action ที่ไม่ได้ active และ `--python-exit-code 1` เพื่อไม่ให้ traceback ถูกนับว่าสำเร็จ
2. ตรวจภาพผลลัพธ์จริงทุกเฟรม ทั้งภาพรวมและจุดน่าสงสัยที่ขนาดเต็ม วาง RGBA บนพื้นทึบก่อนตัดสิน ข้อมูล RGB ในพิกเซลโปร่งใสทำให้ตัวดูบางตัวแสดงภาพที่ไม่ได้มองเห็นจริง
3. ใช้ `sprite-motion-review.py` ตรวจยอดศีรษะ/จังหวะก้มตามโปรไฟล์ที่ประกาศ ไม่ใช่ตรวจข้อต่ออัตโนมัติ คงภาพท่าที่ถูกปฏิเสธไว้เป็นตัวอย่างลบ
4. ใช้ `sprite-contact-review.py` เมื่อเห็นพื้นผิวรองเท้าครบ ถ้ามือบังให้ใช้ `sprite-layer-contact-review.py` กับภาพเลเยอร์ที่เรนเดอร์จริงและ SHA ที่ตรง ห้ามใช้เลเยอร์แยกไปอ้างว่ามองเห็นกายวิภาคในภาพรวม
5. ตรวจชิ้นแขนแยกจาก GPU ว่ายังเป็นเงาร่างต่อเนื่อง ตรวจคอจากบัฟเฟอร์หัว/ตัวจริง แล้วตรวจภาพรวมว่าการบังยังสมเหตุสมผล
6. ใช้ `sprite-coverage-review.py` กับตารางท่า/มุม SHA ภาพ นาฬิกา และผลตรวจด้วยตา การหมุนกล้องต้องมาก่อน alias ห้าม fallback หรือ mirror เงียบ ๆ
7. ทดลองตัวเล่นที่ส่งจริงทุกเฟรม เวลา1×/¼× ปุ่มหยุด/เลื่อน/วน การสลับคลิปซ้อน และภาพ atlas เทียบกับ PNG การแพ็ก lossless ต้องไม่เปลี่ยน RGBA ของต้นฉบับ

เครื่องมือ Python ใช้ Pillow, NumPy และ SciPy; การทดสอบเบราว์เซอร์ใช้ Playwright/Chromium ส่วนริกใช้ Blender4.3.2 รายงานการทดลองระบุ dependency และ SHA ไว้ การเปลี่ยนภาพ จุดผูกริก ขา แหล่งการเคลื่อนไหว หรือนาฬิกาต้องตรวจส่วนที่ได้รับผลใหม่ การแก้คำอธิบายไม่ใช่เหตุผลให้ตรวจฟิสิกส์ทุกอย่างซ้ำ

คำสั่งตรวจชุดที่ส่งออกจากรากแพ็ก:

```sh
python tools/sprite-coverage-review.py catalog.json --output coverage-current.json
python verify-package.py
```

การสร้างใหม่จากสาขาวิจัยใช้ `build-family.py`, `build-reviewer.py`, `check-reviewer.py` และ `verify-family.py` ในเคส v56 ชุดส่งออกมี PNG พร้อมใช้ เครื่องมือตรวจ และโปรไฟล์ตัวอย่าง; ประวัติการลองที่ไม่ผ่านและบัฟเฟอร์วินิจฉัยเต็มอยู่ใน branch research

## Bounded research recipe for each motion

1. Pick2useful primary motion sources and1actual open rig/preset when appropriate. Reuse the existing archive only if it contains the required complete action/transition. Do not count a trailer title shot or held group scene as a gait/attack cycle.
2. Capture a2–5second bounded event with original fileSHA, presentation timestamps, exposure, nativecrop and scene/camera notes. Preserve repeats, holds and unknown delays. If unavailable, record that gap rather than inventing footage or skeletons.
3. Review anticipation/contact/recovery or contact/down/passing/up individually. Record only visible joints/contours; hidden points remain unknown/inferred. Annotate foot/hilt constraints and occlusion transitions explicitly.
4. Author original named poses with actual rig/camera/weights. Run dense reach/sole/contact checks, then sourceview/phase verification before any painted production run. The v20half-cycle error becomes a required negative control.
5. Paint the whole coherent clip and retain raw errors. Compare exact source phase to actual pixels, not labels copied from the source. No frame fitting, mirroring, palette swaps or extraFPS can hide wrong chains/grip.
6. Evaluate per-axis registration, exposure-aware trajectories, phase-appropriate contour/flow diagnostics, contact, item coverage and actual native/slow playback. Keep semantic unknowns independent of numerical results.
7. Only expand facings/items once the bounded exercise has reviewed source/painted evidence. Record new approval against exact pixels and the selected clock; retiming/new drawings/actions require fresh scope.

## Tool work required before motion generalization

- Add independently observed painted soles and explicit logical-root registration to the current unknown-first contracts. [FootSkate Solver's primary documentation](https://research.cs.wisc.edu/graphics/Gallery/FootskateSolver/footskate.html) requires actual per-interval toe/heel constraints; lowestpixel or source clearance isn't footplant proof. Solver was read, not integrated.
- Extend the source adapter to action-specific poses/events/contact intervals and finger/hilt evidence. Current `sprite-motion-audit.py` executes the original walking family; otheractions/rigs need their source adapter and calibrated budgets.
- Reuse the raster reviewer and bound issue ledger, then add reviewed proximal-chain/occlusion annotations and compatible-part swaps. Never manufacture anatomical accuracy from a chart or arbitrary user-enteredlabels.
- Separate bodypose exposure, root/worldspeed, gameplay event andFX lifetime on an authoritative state clock. [Spine's official key guide](https://esotericsoftware.com/spine-keys) documents attachment sequences, draw-order keys andevents, and warns that poses can look acceptable on keys while interpolation is undesirable. Editor frame units aren't a runtimeFPS ceiling. Spine wasn't installed/run in this study.
- Author complete hidden original hair/clothes/body/equipment content and test actual swaps in motion. Current64painted frames are flat previews; complete painted item/frame coverage remains0validated jobs. Earlier source-item planner remains a separate foundation.
- Once visual/parts gates pass, wire a bounded local game adapter for start/stop/turn/interruption and swap tests. The current standalone viewer's direction switching preservesphase but is not proof of correct gameplayturning.

# แผนหลัก Patch 0.0.1 — Source of Truth

เอกสารนี้เป็นแผนหลักสำหรับตัวละคร Patch 0.0.1 และใช้เป็นข้ออ้างอิงเหนือรายงานหรือแผนเก่าที่ขัดกัน คำสั่งใหม่จากเจ้าของโครงการมีผลเหนือเอกสารนี้เสมอ ประวัติการทดลองและผลตรวจอยู่ใน `review/` ส่วนสถานะอาจเปลี่ยนเมื่อมีหลักฐานใหม่

**สถานะ ณ วันที่ 28 ตุลาคม 2026:** หยุดตามคำสั่งเจ้าของเพื่ออ่านแผน งานแก้และย้าย preview ที่ไม่ใช้ยังอยู่ใน working tree และยังไม่ได้ commit หรือ push ไม่มีตัวละครใหม่ที่ครบทุกท่า

### เป้าหมายและสถานะจริง

ส่งตัวละคร Swordsman, Mage และ Archer ชาย/หญิง รวม 6 ตัว ที่มีท่าครบตาม `factory.json`, ใช้ในเกมได้จริง และมี factory ผลิตซ้ำ/เปลี่ยนชิ้นส่วนได้

- **ต้นแบบภาพที่ต้องใช้:** นักดาบตัวสูงชุดเดิมที่เจ้าของชอบจาก `paint-jobs/swordsman-master-cutout-v2/prototypes/basicattack-mesh2motion-reset/` รวมต้นแบบ 4 ทิศ สัดส่วน ความคม และรายละเอียดวัสดุ; รักษาต้นฉบับ 896 ไฟล์
- **เฟรมเด้ง: ยังไม่ผ่าน** Mage มีการเคลื่อนและสัดส่วนผิดใน PNG ต้นทางด้วย; การตรวจ GIF และ Chromium compositor ในชุดที่ทดสอบไม่พบการเลื่อนเพิ่มเติมจาก PNG ไม่ได้หมายความว่า animation ผ่าน
- **ขนาด/size shift: ยังไม่ผ่าน** ล็อก canvas และ scale แล้ว แต่รูปร่างในภาพยังเปลี่ยนระหว่างเฟรมและยังไม่ได้เทียบทั้ง 6 ตัวกับนักดาบตัวสูงจนผ่าน
- ปัญหาหัวขาดของ Mage ลดได้ในภาพตรวจโดยใช้หัวและตัวจากเฟรมเดียวกัน แต่ยังไม่ใช่ sprite ที่ผ่านหรือเปลี่ยนหัวได้จริง
- สถานะรวม **0/6 ตัวละครใหม่ที่ครบทุกท่า, 2/96 งานนำเข้าทางเทคนิค**; จำนวนนี้ไม่ใช่ตัวละครพร้อมเล่น และ Mage ใหม่ยังไม่เข้าเกม
- ตรวจเกมพบ package `patch001` ทั้ง 6 ไฟล์ไม่มีใน Git tree และหน้าสร้างตัวละครปกติยังเริ่มไม่ได้
- ตามคำสั่งให้เก็บตัวที่ไม่ใช่ออก: ใน working tree ได้ย้าย preview `swordsman-male-v3`, `v3-painted`, `v3-painted-v2` ไป `authoring/characters/factory-v3/unused/` และเริ่มถอดทางเลือกที่เรียก preview เหล่านี้ **การเปลี่ยนชุดนี้ยังไม่ commit หรือ push**; หยุดไว้เพื่อให้ตรวจแผนก่อน

### Workflow ผลิตที่ตกลงกัน

1. ตรวจรายการท่า, source และ reuse กับ `factory.json`/ledger; ท่าต่างจำนวนเฟรมห้าม alias ผิด เช่น Mage BasicAttack/SkillAction 24 เฟรมกับ CastRelease 16 เฟรม
2. เลือก motion ที่เหมาะ โดยเริ่มจาก Mesh2Motion และเทียบกับ ActionForge, motion เก่า, Rokoko หรือ Mixamo; เปิดใน Blender ตรวจถ่ายน้ำหนัก, แขน, ข้อมือ, grip, เท้า, timing, root motion และ recovery
3. ล็อกกล้อง orthographic, มุม, พื้น, root และ scale ทั้งท่า; เทียบสัดส่วนทั้ง 6 ตัวกับนักดาบตัวสูงเดิม ใช้ source guide 1536×1536, authoring 768×768, runtime 240×240, root 120,172 และ reference height 88 ตาม policy
4. วาด **ตัวเต็มพร้อมชุดของแต่ละเฟรมตาม rig** ตรวจ key poses ก่อน แล้วตรวจเฟรมคั่นจริง; ไม่ประกอบแขนขาที่สร้างแยกกันและไม่ตรึงขาเพื่อซ่อนเด้ง
5. เมื่อ master ผ่าน จึงไดคัท **BodyCostume** (ตัว ชุด แขน มือ ขา), **HeadHair**, **Weapon** จากเฟรมและกล้องเดียวกัน; เพิ่มชั้นมือบังอาวุธ/FX หน้า-หลังเฉพาะเมื่อจำเป็น
6. ประกอบกลับและตรวจพิกเซลกับ master, ขอบบนพื้นสว่าง/มืด, ลำดับบัง, มือจับ, ส่วนที่ต้องวาดใต้ชิ้นที่เปลี่ยน และการเคลื่อนไหวเต็มลำดับ; exact pixels เป็นเพียงหนึ่งเกณฑ์ ไม่ใช่ visual approval
7. แพ็กแยก sprite sheets พร้อม metadata/anchors/timing, ทดสอบการเปลี่ยนผม ชุด อาวุธทีละ slot และพร้อมกัน แล้วตรวจการผลิตซ้ำ
8. นำเข้าเกมจริงและตรวจ gameplay/transition, ขนาดบนแผนที่จริง, ทิศ, วน/one-shot, การปล่อย projectile และ FX; บันทึกหลักฐานและรายงาน GitHub

### แผนแก้ปัญหาปัจจุบัน

- **ตัวผิด:** จัด V3 preview ที่ไม่ใช่นักดาบตัวสูงไว้ `unused`, ปิดทางเลือกที่เรียกใช้ ตรวจไม่ให้สร้างกลับโดย default, ตรวจ baseline 896 hash แล้ว commit/push หลังกลับมาทำงาน; อย่าลบ master หรือ motion ที่ยังต้องใช้
- **เด้ง/size shift:** แยก full-frame registration จากการเปลี่ยนรูปร่างภายใน master. ตรวจ head/neck/shoulder/hip/knee/ankle และเท้าที่ปักพื้นเทียบ guide พร้อมตรวจทีละเฟรมและ GIF ความเร็วจริง/ช้า. แก้ master ของเฟรมนั้นด้วยภาพที่ยึด guide; ใช้ global fit คงที่ ไม่ scale จาก bbox และไม่คัดลอกขาจากอีกเฟรม. จุดสัมผัสที่ยืนยันแล้วคลาดไม่เกิน 1 runtime pixel หลังหัก motion ที่ตั้งใจไว้; จุดที่ถูกบังต้องตรวจ landmark ไม่เดาให้ผ่าน
- **Mage หัวขาด:** เริ่มจากหัวและตัวเฟรมเดียวกัน; ตรวจ collar/neck ทุกเฟรมและวาดพื้นผิวที่ถูกบังจริงก่อนทดสอบเปลี่ยนหัว. ส่วนคทา/มือที่ยังติด BodyRest หรือมีเศษชุดอยู่ในชั้นอาวุธไม่ผ่าน
- **Archer:** ให้มือจับคันธนูต่อเนื่อง, ตรวจจุดจับ สายธนู ลูกธนู ช่วงดึง/ปล่อย และ recovery; ขอบหัวห้ามกินแขน ถุงมือ หรือ quiver
- **Swordsman:** ใช้ basic attack ใหม่ที่ดูเบสิคและเก็บท่าที่เลือกไว้เป็น skill ตาม motion. ตรวจหลังมือ ข้อมือ ดาบตาม guide และ trail ยาวหนาตามแรง เริ่มหลังฟัน กวาดไปข้างหน้า ไม่เกินช่วงกวาด แยกบังหน้า/หลัง และไล่เฉดแบบของเรา
- **GIF/loop:** loop ใช้กับท่าที่วนจริง; ท่าโจมตีตรวจ one-shot และการกลับ ready/idle. ตรวจ PNG → GIF → compositor → เกมแยกกัน ไม่ใช้ GIF ซ้ำวนแทน transition ในเกม

### ลำดับปิดงาน

0. ปิดการย้าย preview ผิดไป unused, audit ledger/alias, กล้องและ baseline ให้ตรวจย้อนหลังได้
1. ปิด pilot Swordsman เดิม + Mage cast + Archer basic ทั้งสองเพศ ผ่านครบ motion → master → cutout → FX → เกม ก่อนขยายงาน
2. ผลิต Idle/CombatIdle/Walk/Run/Sprint ทุกตัวและทุกทิศ พร้อมตรวจขนาดและการเปลี่ยนท่า
3. ผลิตโจมตี/ร่าย/ท่าเฉพาะอาชีพ พร้อม event ที่ตรงจังหวะและ trail/ลูกธนู/เวท
4. ผลิต Hit/Death/Sit/Respawn/Interact/Pickup/ItemUse และท่าที่เหลือให้ครบ config
5. ทำผม ชุด และอาวุธใหม่ทั้งชายหญิงอย่างน้อยชุดทดลองตามอาชีพ: Swordsman BasicAttack, Mage CastRelease, Archer BasicAttack ครบ 4 ทิศ; ชุดใหม่ต้องเปลี่ยนรูปทรง ไม่ใช่แค่ recolor
6. แพ็ก 6 ตัวและทดสอบจริงทุกท่า ทุกทิศ การเปลี่ยนชิ้นส่วน การกลับท่า และการผลิตซ้ำ

### เกณฑ์ส่งงานและรายงาน

ส่งว่าเสร็จได้เมื่อ 6/6 ตัวมี binding ทุกท่า ใช้งานจริง, master ไม่เด้ง/ไม่ size shift ผิด, ไม่มีหัวขาด/อาวุธหลุด/ขอบตัด, loop และ one-shot พร้อม transition ผ่าน, sprite sheets แยกส่วนและ metadata ใช้งานได้, variants เปลี่ยนได้จริง, source/คำสั่งผลิตซ้ำครบ และมีภาพ/GIF กับ capture จากเกมจริง

ทุก checkpoint รายงานบน GitHub พร้อม commit, coverage จริง, GIF/ภาพ, ข้อผิดพลาดที่ยังเปิด, version/hash/คำสั่ง และการทดสอบที่รันจริง. ไม่ใช้ test ผ่านหรือภาพทดลองตัวเดียวแทนการยอมรับคุณภาพทั้งหมด

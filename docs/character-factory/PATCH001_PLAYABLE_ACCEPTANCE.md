## Required result

Each of the six characters must have all actions listed in
`authoring/characters/factory-v3/patch-0.0.1/factory.json`, with class-specific
actions such as SpinAttack, TrapPlace and ArrowRain. Movement/general states use
eight actual views. Physical attacks and casting use four diagonal views and
the owner's facing map. No mirroring or silently substituted missing action.

The final acceptance pass must demonstrate:

1. Ordinary creation, sex/class selection, movement and facing in the real game.
2. Basic attack, every authored skill family, mobility, hit/death/respawn,
   interactions, pickup, item use and sitting, with correct action transitions.
3. Contact/projectile release aligned to gameplay through explicit semantic
   events. The game passes `skill1`–`skill4`; resolve the actual `definition.id`
   before choosing SpinAttack, TrapPlace or ArrowRain.
4. Source-consistent body/head/foot motion and stable figure scale at game size.
   Inspect normal/slow playback and action boundaries. A fixed canvas/root alone
   does not establish a stable painted character.
5. Clean HeadHair/BodyCostume/Weapon boundaries, anatomical hands gripping props,
   correct visible draw order and persistent accessories. Pixel recomposition
   alone does not certify semantic masks or hidden surfaces.
6. Short, correctly timed independent sword trails, including foreground and
   background occlusion. Back trail passes stay behind the body; front passes
   stay under the hand occluder.
7. Save/reload and no missing resources or stale application-shell versions.
8. One full hairstyle/costume swap action per class across its four real views,
   sharing compatible poses, weapon and FX.

## Implemented runtime bridge

`patch001-characters.js` is generated by
`tools/character_factory_v3/export_runtime_character_policy.py`. It declares six
distinct package paths, class-specific motion requirements and combat bindings.
Wardrobe and creation/studio selection use the240px padded canvas with root
`[120,172]`. The studio inspects the actual cutout roles and distinguishes four
authored attack/cast views from eight movement views. Application cache106
includes the policy.

`tools/character_factory_v3/pack_patch001_character.py` consumes complete imported
same-frame cutouts and **explicit** per-action timings/events. It checks asset
pixel hashes, pose/camera/fit IDs, all requested directions and core roles, then
validates the resulting definition with the real JavaScript runtime before
writing a new package. It never invents missing artwork, source poses, sockets,
contact times or approval. Existing packages are not silently overwritten.

Timing input is an object keyed by action name; each entry supplies `durations`
and, for contact/release actions, an `events` list with `name`, `frameIndex`,
`timeMs`, and `phase`. Looping locomotion can also supply a measured
`cycleDistance`. These are authoring inputs, not synthetic default timings.

## Actual quality findings and corrections

- Separately reducing adjacent head/body cutouts produced3,880 changed pixels
  across the16 actual male Archer NW frames. Reducing the complete master once,
  then assigning exclusive visible pixel ownership, reconstructs all16 reduced
  masters exactly. Independent FX are excluded from that partition. Hidden
  overlapping surfaces are rejected rather than silently discarded.
- The initial head masks included hair fringe in the body, glove/string pixels
  in the head and small neck/accessory fragments. An identity-specific bounded
  ownership proposal plus manual profiles addresses those boundaries without
  changing a single complete-master pixel. It remains a partial cutout study;
  BodyCostume still includes the weapon.
- Actual weighted head/head_leaf and foot/ball/leaf geometry is re-evaluated in
  Blender. All16 replayed poses match retained rig landmarks exactly. This
  helps distinguish source motion from painting drift. The painted head-motion
  residual is still large in some poses; it is a diagnostic signal, not a pass.
- Local foot repairs and a whole-strip constrained repaint are retained as
  experiments. The full-strip generator still changes scale/pose placement;
  that candidate is rejected. No per-frame figure recentering or full-body warp
  is used to hide this failure.

cutouts, trim only transparent storage margins, retain each integer offset and
compose on the full canonical source canvas before one final runtime resize.
Independent-layer reduction cannot preserve hidden underlays and is not the
default. The explicit `visible-partition` mode remains for exclusive-mask studies.

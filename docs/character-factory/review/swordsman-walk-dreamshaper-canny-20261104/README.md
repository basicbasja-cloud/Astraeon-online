# Walk SW 00 — DreamShaper and Canny ControlNet experiment

**Single-frame draft rejected for intake.** A second CPU img2img model, `Lykon/dreamshaper-8` revision `a7e52b98680b1ba8ff7bce97c7f9f2e2e5337917` (model card: CreativeML OpenRAIL-M), was combined with the same Canny ControlNet revision, input art, seed and low settings as the previous SD 1.5 v2 trial. [Guide, input and result](comparison.png). The image is more detailed, but changes the character's face, bare hand, armor and costume and still does not prove anatomical placement or motion consistency. Do not import it or expand it across directions; no original or runtime files changed. Model/ControlNet licenses must be reviewed for the intended use.

The result and receipt are in `patch-0.0.1/research/swordsman-walk-dreamshaper-canny-20261104/`. The local process took about two minutes on CPU. The existing setup script accepts `ASTRA_BASE_REPO=Lykon/dreamshaper-8 ASTRA_BASE_REVISION=a7e52b98680b1ba8ff7bce97c7f9f2e2e5337917` and a fresh `ASTRA_CONTROLNET_ROOT`; it installs to temporary storage and downloads pinned model components. Run `propose_walk_canny_control.py` with the DreamShaper snapshot as `--base`, that revision as `--base-revision`, the Canny snapshot as `--control`, the inputs from the prior study, and `--strength 0.25 --conditioning 0.4 --steps 20`. The receipt records the script hash, input hashes and seed. Model generation was not repeated, so exact reproducibility remains unverified. Temporary models can disappear on restart.

This is not an animation, same-frame cutout, asset swap or game test. Coverage remains 2/96 technical imports and 0/6 completed characters. Previous SD setup, baseline references and limitations are in `../swordsman-walk-canny-control-20261104/README.md`.

# Walk SW 00 — projected pose plus reference-image adapter

**Single-frame drafts rejected for intake.** The CPU experiment combines DreamShaper 8, OpenPose ControlNet using source Blender joint projections, and `h94/IP-Adapter` revision `018e402774aeeddd60609b4ecdb7e298259dc729` (model card lists Apache-2.0). [Comparison](comparison.png), left to right: mannequin guide, original draft, first result at strength 0.25/reference scale 0.7, second result at strength 0.10/reference scale 1.0. Both change the bare hand, armor, costume and appearance relative to the illustrated character; neither proves the required pose, image quality or continuity. The pose control does not contain sword or fingers. No source or runtime asset changed.

The reference encoder's 521-tensor FP32 safetensors was converted to FP16 using a bounded-memory script to fit this CPU workspace. Source encoder SHA-256: `6ca9667da1ca9e0b0f75e46bb030f7e011f44f86cbfb8d5a36590fcd7507b030`; converted encoder SHA-256: `6914c90a48f1fa3c2c415ccf3361a38bfcbd9cbd0c15f39f1dbbafb3b4da598d`; adapter SHA-256: `289b45f16d043d0bf542e45831f971dcdaabe18b656f11e86d9dfba7e9ee3369`. Keys matched and three selected tensors matched FP16 conversion; the full real encoder was not exhaustively compared. A focused synthetic conversion test passed, including integer preservation and refusal to overwrite. The reference embedding was regenerated on the same machine and matched exactly as a tensor.

The second image was regenerated with the same saved embedding, seed and settings on the same CPU environment; both PNG SHA-256 hashes were `10306f85cf949d87441221063b256d5807f47b64f1aeed5989754064cec2b738`. This is a one-frame same-environment reproduction, not cross-platform or full-action reproduction. Raw results, receipts, embedding and historical v1 runner are retained under `patch-0.0.1/research/swordsman-walk-pose-ipadapter-20261104/`.

For a new temporary environment, follow the DreamShaper/OpenPose setup in `../swordsman-walk-dreamshaper-openpose-20261104/README.md`, then set `ASTRA_CONTROLNET_PY` to its `py` directory and run `bash tools/character_factory_v3/setup_walk_ipadapter_cpu.sh` with a fresh `ASTRA_IP_ROOT` on a temporary filesystem with at least 4 GB. The script downloads the pinned IP-Adapter, validates the original and converted encoder hashes, and removes only its own newly created download cache after conversion. Generate an embedding with `encode_walk_ip_reference.py`, then invoke `propose_walk_pose_ipadapter.py` using the local model snapshots, adapter directory, embedding, saved input directory and `--strength 0.1 --steps 30 --ip-scale 1.0`. All output directories must be fresh. Model caches are temporary and may vanish on restart; review upstream model licenses before production use.
